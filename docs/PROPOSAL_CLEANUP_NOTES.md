# Proposal-Only Cleanup Notes

## What This Cleans

The cleanup SQL is designed to remove proposal-only test data from Supabase:

- `public.axiom_proposals`
- `public.axiom_stripe_events` rows where `proposal_id is not null`

This clears proposal drafts, secure client proposal access tokens, proposal PDF path references, proposal delivery state, manual proposal payment state, and proposal-linked Stripe event ledger rows.

## What Is Intentionally Preserved

The cleanup does not delete:

- Auth users
- `public.axiom_customers`
- `public.axiom_service_requests`
- `public.axiom_orders`
- `public.axiom_workflow_submissions`
- `public.axiom_audit_reports`
- `public.axiom_client_workspaces`
- `public.axiom_workspace_documents`
- `public.axiom_workspace_deliverables`

The SQL also preserves non-proposal Stripe event rows by only deleting from `public.axiom_stripe_events` where `proposal_id is not null`.

## How To Run Safely In Supabase

1. Open Supabase SQL Editor.
2. Open `docs/sql/CLEAN_PROPOSALS_ONLY.sql`.
3. Run the count queries first and review the delete-target counts.
4. Review the proposal PDF paths listed under the manual storage review section.
5. Run the full transaction as written. It ends with `rollback;`, so it will not permanently delete anything yet.
6. Confirm the post-delete verification rows show:
   - `public.axiom_proposals` would be `0`
   - proposal-linked `public.axiom_stripe_events` would be `0`
   - preserved tables still have their expected counts
7. Only after confirming the output, replace `rollback;` with `commit;` and run again.

## Frontend Verification After Cleanup

After running the committed cleanup:

- Open `/admin/proposals`.
- Confirm the proposal draft list is empty.
- Confirm submitted proposal/service-request clients still appear where expected.
- Confirm customers, orders, workflow submissions, audit reports, and client workspaces are still visible in their existing admin/client areas.
- Open the public/client proposal link from an old email and confirm it no longer exposes proposal content.

## Manual Storage Review

The cleanup SQL does not delete files from Supabase Storage.

Proposal PDFs generated by the proposal engine are stored in the private bucket:

- Bucket: `axiom-client-deliverables`
- Path pattern: `proposals/{customer_id_or_unassigned}/{proposal_id}/{timestamp}-proposal.pdf`

Use the `pdf_file_path` rows listed by `CLEAN_PROPOSALS_ONLY.sql` before deletion to decide whether to remove those files manually from Supabase Storage. Do not delete anything under non-proposal paths such as report files, workspace documents, or deliverables unless reviewed separately.
